ARGOS OS · V3 · INTERNAL PRODUCTION

ArgosOS

A vertical operating system for small law firms: intake, CRM, collections, and audit in one governed environment. Argos runs Tech Frog's own back office — we are client zero.

  • Typed verification engine. Claims are typed, checked, and gated before they act. An unverified claim cannot trigger a downstream step.
  • Hash-chained audit log. Every material action is SHA-256 chained to the one before it. Tampering doesn't hide — it breaks the chain visibly.
  • Collections state machine. Receivables move through explicit states with owners and timers. Nothing sits in "someone should follow up."
  • Model-agnostic AI layer. Anthropic, OpenAI, or local inference. The workflow doesn't care which model answers.

Findings on record: V2 went through a structured hostile review of our own design. V3 answered it — fully typed codebase, test coverage, and a written resolution of every finding. The review documents ship with the system.

SYS/05 METHOD

The same sequence, every time.

Order matters. We don't build before we map, and we don't hand over before we document.

  1. Map

    Observe how work actually moves — not how the org chart says it should. Every entry point, handoff, and drop point, written down.

  2. Design

    Specify the system in writing: states, owners, failure modes, escalation. If the spec can't say what happens when it breaks, it isn't done.

  3. Build

    Typed, tested, on boring and reliable tools. Nothing clever where dependable will do.

  4. Verify

    Human review gates on anything that acts. Hash-chained logs on anything that matters. The system is built to be checked.

  5. Document

    Runbooks, architecture notes, and training. The test: a new hire can operate it from the documentation alone.

  6. Maintain

    Monitoring and care after handover, so failures surface before clients notice — and fixes land before they escalate.

If it can't be verified, it doesn't ship.

Boring tools. Sharp systems.

Documentation is a deliverable, not an apology.

The client owns everything — code, docs, credentials.

We say what we don't know. In writing.

        When can engagements begin? +

        Will our data be used to train AI models? +
        
No. Cloud AI runs through zero-retention API configurations. Sidebar runs entirely on hardware in your office. Training on client data is contractually off the table.

      

      

        Do you resell software or hardware? +
        
No margins on other people's products. We specify, build, and configure — you hold the licenses, the credentials, and the code. Our incentive is that the system works, not that you buy more of it.

      

      

        What if we're not technical? +
        
Expected. Every system ships with documentation and training. The test we hold ourselves to: a new hire should be able to run it from the runbook alone.

      

      

        How is AI kept from being confidently wrong? +
        
Structurally. Outputs pass typed verification and human review gates before they act, and every step lands in a hash-chained log. The system is built to be checked — trust comes from the architecture, not the model's tone of voice.

      

      

        What does it cost? +
        
Workflow audits are fixed-fee. Builds are fixed-scope. Ongoing care plans start at $1,200 per month. No hourly billing — meters change incentives, and not in your favor.

On-site across the Austin corridor. Remote elsewhere, with the same documentation standard — the runbook doesn't care about the zip code.
